# Decision index

One line per ADR: what we decided and why. ADRs are never edited after acceptance; a later ADR supersedes. Use this page as the spine of the presentation.

| # | Decision | Why |
|---|---|---|
| [0001](0001-architecture.md) | Monorepo; Next.js UI that knows nothing of Supabase; separate Hono API; multi-tenant; open sign-up creating an Owner; permission-based RBAC; k-of-N approvals | Clear boundaries, security enforced below the UI, matches a financial approval process |
| [0002](0002-gateway-ledger-and-hardening.md) | Gateway as the only published port; rules in Postgres; server-side sessions; one hash-chained `deal_events` ledger | A valid JWT must not bypass rules; audit trail must be tamper-evident |
| [0003](0003-tooling-and-standards.md) | Org engineering standards + project overlay; Vitest; Dockerfiles; CI docker build | Reproducible, explainable quality gates |
| [0004](0004-csp-storage-bff.md) | Nonce-based CSP and hardening headers; Hono is the BFF; `ObjectStore` port (fs + Cloudflare R2); avatars re-encoded | Browser hardening without breaking single-origin; reviewer path needs no cloud account |
| [0005](0005-oxc-toolchain-and-git-hooks.md) | oxlint + oxfmt, TypeScript 7, Husky + lint-staged + commitlint | Removes the TypeScript pin, faster, same rule coverage we need; hooks help but CI decides |
| [0006](0006-tailwind-design-layer.md) | Tailwind v4; DoorSprint tokens in `packages/ui`; cookie theme; feature layering with lint boundaries | Accessible, themeable design system with a tested contrast matrix; strict CSP; Next has no Nuxt-style layers so we use packages + boundaries |
| [0007](0007-request-layer-tanstack-query-vs-alova.md) | Keep TanStack Query; alova not adopted | Our realtime/tenant/optimistic needs are documented in TanStack; alova's App Router and cache behaviour are unverified |
| [0008](0008-container-images-and-ci.md) | Digest-pinned multi-stage Dockerfiles, bundled API, Next standalone, Caddy gateway, hardened compose, CI with hadolint/Trivy/gitleaks/smoke and gated GHCR publish | Smallest runtime surface and a delivery path that fails closed; every claim was run, and what could not be run is listed |
| [0009](0009-ui-direction-from-mockup.md) | Take the mockup's structure, not its assets; re-derive palette for contrast; per-currency totals; no SSO/magic link/CVC branding; Next 16 `proxy.ts`, nonce CSP confirmed | The mockup's own palette fails WCAG AA in several uses (measured); a literal copy would ship accessibility failures, a misleading total and someone else's brand |
| [0010](0010-ai-assisted-pr-review.md) | Advisory AI PR review on Cloudflare Workers AI (free 10,000 neurons/day, no training on customer content), non-blocking, label-triggered re-runs. **Corrects an earlier wrong recommendation:** GitHub Models was retired 2026-07-30 and `actions/ai-inference` v3 is Copilot-only | Free, advisory, reuses the Cloudflare account; verified on primary sources, 30 offline tests; first live run needs the owner's two secrets |
| [0011](0011-closing-soon-countdown-and-alert.md) | Closing soon: 60-day window, live day-resolution countdown, server-side idempotent alert at 5 days to the assigned team (fallback Owner/Admins), in-app plus email digest, audited in the ledger | The alert must fire when nobody is logged in and must never be lost or duplicated; a date field supports day precision, not seconds |
| [0012](0012-code-coverage.md) | V8 coverage over all source files, thresholds that fail the build (higher for shared and api), CI summary and artifact; mutation testing named as the next step | The old 100% was misleading (only loaded files counted); V8 and Istanbul gave identical numbers on our code; coverage is a backstop, not a quality measure |
| [0013](0013-supabase-stack-for-compose.md) | Five Supabase services on an internal network (db, auth, rest, realtime, Envoy), no Studio/pooler/storage/etc., Mailpit added, our own keys | Measured: 446 MiB vs 1,244 MiB and 2.5 GB vs 7.3 GB of images; everything we rely on was exercised against the real stack |
| [0014](0014-supabase-in-compose.md) | Supabase integrated: internal network, keys derived from one secret, zero-setup dev-only defaults plus `make env`, vendored files via script, own migration runner and pgTAP runner, real-route healthcheck, sabotage-proven smoke test | Reviewers need one command and no accounts; the network is the boundary; each check was shown able to fail |
| [0015](0015-sessions-in-postgres-and-api-service-role.md) | Sessions in a Postgres table (only a hash of the session id stored, tokens encrypted by the API), and JWT-less work through a narrow `api_service` role reached via PostgREST, not the service-role key | Survives restarts and supports revoke and closing sockets; keeps the service-role key out of request handlers; the privileged surface is a short, testable list of functions |
| [0016](0016-gotrue-admin-calls-from-the-auth-module.md) | GoTrue admin calls (create user, set password, confirm email) use a 30-second `service_role` JWT minted privately inside `apps/api/src/auth/gotrue.ts`; a test fails if that role string appears anywhere else | GoTrue has no narrower role for these calls and public sign-up is disabled; confinement is enforced by a test and the lint boundary, not by convention |
| [0017](0017-patched-caddy-gateway-build.md) | Rebuild pinned upstream Caddy v2.11.7 with go-jose v4.1.6 and x/net v0.60.0 while keeping the pinned stock Alpine runtime | The latest upstream image contains fixed high-severity dependencies; a narrow, reproducible upstream rebuild clears them without suppressing findings or changing the gateway architecture |
| [0018](0018-approval-gate-core.md) | Initial IC approval gate: tenant-configured quorum; submit-time approver snapshot; approve/reject only; decision and signing are database-atomic and ledgered | Preserves maker-checker, fail-closed quorum, immutable role definitions, and a reviewable first slice; absence/delegation are explicit follow-up work |
| [0019](0019-approval-absence-and-reassignment.md) | Self-managed absence windows; fail-closed quorum reachability; Owner/Admin reassignment that preserves the original approval slot | Keeps unavailable members out of the reachable quorum and makes replacements explicit and auditable without rewriting the request snapshot |
| [0020](0020-approval-delegation.md) | Tenant-opt-in, time-bounded approval delegation; proxy preserves the original slot and may cast only one vote per request | Adds coverage for temporary absence without self-approval, extra quorum weight, or mutable request snapshots |
| [0021](0021-quorum-alerts.md) | Hourly idempotent in-app alerts when a pending request cannot reach its snapshotted quorum | Makes a stalled approval visible to its requester and tenant administrators without weakening fail-closed signing |
| [0022](0022-custom-role-management.md) | Tenant-scoped custom roles saved through guarded database functions with SoD checks and append-only audit | Gives role managers flexibility while keeping system roles immutable and authorization enforced in Postgres |
| [0023](0023-web-control-primitives.md) | Shared native web control styling on semantic tokens; no React UI dependency for basic primitives | Fixes cross-page control inconsistency while preserving native behavior and the existing design layer |
| [0024](0024-ic-approval-sla-escalation.md) | One-time in-app escalation after 24 hours on the existing IC approval gate; no approval gates at other stages | Makes overdue review visible without changing quorum, auto-deciding, or expanding the approved workflow |
| [0025](0025-deal-kanban-board.md) | Add a drag-and-drop Board view while preserving keyboard stage controls in List view; use the existing stage machine and versioned API | Delivers the requested visual pipeline without duplicating authorization rules or removing accessible operation |

## How we record a decision (so every step has its reason)
Context, decision, why, alternatives, what we verified locally versus only read, known gaps, and when to revisit. Anything unconfirmed is marked **verify**.
